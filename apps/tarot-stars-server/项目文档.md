## 1. 项目概述

**项目名称**: Tarot Stars
**目标**: 构建一个基于 Telegram Bot 和 Mini App 的多语言塔罗牌占卜应用。
**架构**: 前后端分离，采用 DDD 领域驱动设计模式。

## 2. 整体架构与分层设计

本项目采用 **DDD (领域驱动设计)** 分层架构，确保高内聚、低耦合和业务逻辑的清晰性。

*   **领域层 (Domain Layer)**: 包含核心业务实体、值对象、领域事件、领域服务接口和仓储接口。代表了业务的核心规则和概念，不依赖任何技术实现。
    *   **AI 任务**: 定义纯业务逻辑相关的接口和类型。
*   **应用层 (Application Layer)**: 协调领域对象，封装特定用例的业务流程。它不包含业务规则，而是 orchestrates 领域层来完成用例。
    *   **AI 任务**: 实现用例服务 (Use Cases)，调用领域服务和仓储接口完成业务流程。
*   **基础设施层 (Infrastructure Layer)**: 负责技术实现细节，如数据库交互、外部API调用、工具类等。实现了领域层的仓储和服务接口。
    *   **AI 任务**: 实现数据库连接、仓储实现、第三方服务集成（如多语言工厂）。
*   **接口层 (Interfaces Layer)**: 处理用户界面和外部系统交互。包括 REST API 和 Telegram Bot 接口。
    *   **AI 任务**: 实现 REST API 路由、控制器和 Telegram Bot 命令/回调处理器，负责数据输入验证和输出格式化。

#### 3.2.3 每日占卜模块 (Daily Reading)

*   **目标**: 实现每日一牌功能，记录用户抽牌历史，并提供动态解读。
*   **领域实体 (位于 `src/domain/entities/dailyReading.ts`)**:

    ```typescript
    import { ObjectId } from 'mongodb';

    export interface DailyReading {
      _id?: ObjectId;
      userId: ObjectId;            // Associated User ID
      cardId: string;              // Tarot Card ID
      isReversed: boolean;         // True if card is reversed, false otherwise
      date: number;                // Reading date timestamp (milliseconds, typically start of day)
      createdAt: number;           // Creation timestamp (milliseconds)
    }
    ```

*   **仓储接口 (位于 `src/domain/repositories/IDailyReadingRepository.ts`)**:

    ```typescript
    import { DailyReading } from '../entities/dailyReading';
    import { ObjectId } from 'mongodb';

    export interface IDailyReadingRepository {
      findByUserIdAndDate(userId: ObjectId | string, date: number): Promise<DailyReading | null>;
      findRecentByUserId(userId: ObjectId | string, limit: number): Promise<DailyReading[]>;
      create(reading: Omit<DailyReading, '_id' | 'createdAt'>): Promise<DailyReading>;
    }
    ```

*   **核心业务流程 (在 `TarotUseCases` 中实现)**:
    *   **`getDailyReading(userId, language)`**:
        1.  检查用户今天是否已抽牌 (`hasReadingToday(userId)`)。
        2.  如果已抽，返回今日已抽的卡牌及其解读。
        3.  如果未抽：
            *   随机抽取一张 `LocalizedTarotCard`。
            *   随机决定正逆位 (50% 概率)。
            *   保存 `DailyReading` 记录（`userId`, `cardId`, `isReversed`, `date`）。
            *   基于卡牌和正逆位生成个性化解读。
            *   更新用户总抽牌次数。
            *   返回抽牌结果（包括卡牌信息和解读）。
    *   **AI 任务**: 实现上述流程，特别是 `generateInterpretation` 方法应根据 `LocalizedTarotCard` 的 `meaning.upright` 或 `meaning.reversed` 字段返回内容。

#### 3.2.5 REST API 模块 (Interfaces Layer)

*   **目标**: 为前端 Mini App 提供数据服务，所有敏感操作需进行 Telegram WebApp 数据认证。
*   **技术**: Koa。
*   **文件路径**: `src/interfaces/api/routes/*.ts`, `src/interfaces/api/middleware/auth.ts`.
*   **认证与安全**:
    *   **Middleware (`auth.ts`)**: 每一个需要认证的 API 请求，都必须携带 `X-Telegram-Web-App-Data` header。中间件负责验证 `initData` 的完整性和时效性。
        *   **AI 任务**: 实现 `validateTelegramWebAppData` 函数，使用 `crypto` 模块进行 HMAC 256 哈希验证。
    *   **CORS**: 严格配置 CORS，只允许 Telegram WebApp 的域名访问。
    *   **Validation**: 使用 Joi 等库对所有请求体和查询参数进行严格验证。
*   **API 端点**:
    *   **用户相关**:
        *   `POST /api/tarot/user`: 创建或更新用户（Mini App 启动时调用）。
            *   **Request**: `{ initData: string, telegramId: number, firstName: string, ... }`
            *   **Response**: `{ user: User }`
        *   `PUT /api/tarot/user/:userId/language`: 更新用户语言偏好。
            *   **Request**: `{ languageCode: string }`
            *   **Response**: `{ success: boolean }`
    *   **每日占卜**:
        *   `POST /api/tarot/daily-reading`: 获取或生成每日塔罗牌解读。
            *   **Request**: `{ userId: string, language: SupportedLanguage }`
            *   **Response**: `{ reading: DailyReading, card: LocalizedTarotCard, interpretation: string }`
        *   `GET /api/tarot/has-reading-today/:userId`: 检查用户今日是否已抽牌。
            *   **Response**: `{ hasReading: boolean }`
    *   **历史记录**:
        *   `GET /api/tarot/history/:userId`: 获取用户历史抽牌记录（最近10条，可带分页参数）。
            *   **Response**: `{ history: Array<{ reading: DailyReading, card: LocalizedTarotCard, interpretation: string }> }`
    *   **卡牌相关**:
        *   `GET /api/tarot/cards`: 获取所有卡牌简要信息（可选 language 参数）。
        *   `GET /api/tarot/cards/:cardId`: 获取指定卡牌的详细信息（需 language 参数）。
        *   `GET /api/tarot/categories`: 获取所有卡牌分类（需 language 参数）。
        *   `GET /api/tarot/suits`: 获取所有花色信息（需 language 参数）。
        *   `GET /api/tarot/languages`: 获取所有支持的语言列表。

## 5. 跨模块协作与流程

**AI 任务**: 理解并实现以下核心流程的逻辑编排。

### 5.1 用户抽牌完整流程 (Bot 触发)

1.  **用户通过 Telegram Bot 发送 `/daily` 命令。**
2.  **Bot 接口层**: 接收命令，调用 `TarotUseCases.getDailyReading()`。
3.  **应用层 (TarotUseCases)**:
    *   调用 `IUserRepository` 查询用户。
    *   调用 `IDailyReadingRepository` 检查今日是否已抽牌。
    *   如果未抽：
        *   调用 `ITarotService.drawRandomCard()` 随机抽取本地化卡牌。
        *   生成正逆位。
        *   调用 `IDailyReadingRepository.create()` 保存抽牌记录。
        *   调用 `IUserRepository.incrementTotalReadings()` 更新用户统计。
        *   调用 `ITarotService.getInterpretation()` 生成解读。
    *   返回抽牌结果（卡牌信息 + 解读）。
4.  **Bot 接口层**: 格式化抽牌结果，通过 Telegram API 发送给用户。

### 5.2 API 请求处理流程 (Mini App 触发)

1.  **Mini App (前端)**: 用户在 Mini App 中请求每日占卜 (或查看历史等)，通过 `tarotApi.dailyReading(...)` 发送 POST 请求到后端 `/api/tarot/daily-reading`，携带 `X-Telegram-Web-App-Data` 头。
2.  **API 接口层 (Express API)**:
    *   **TelegramAuth Middleware**: 验证 `X-Telegram-Web-App-Data` 中的 `initData`。如果验证失败，返回 401 Unauthorized。
    *   **Router**: 调用 `TarotUseCases.getDailyReading()`。
    *   **应用层 (TarotUseCases)**: 同上（用户抽牌完整流程的步骤3）。
    *   **Router**: 返回 JSON 响应给 Mini App。
3.  **Mini App (前端)**: 接收响应，更新 Redux 状态，渲染 UI。
